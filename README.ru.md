# Open Tooling

Общий контракт репозитория, CLI и GitHub Actions для семейства `open-*`.

Спецификации остаются в отдельных репозиториях. Здесь находятся единые проверки состава, сборка артефактов и выпуск. Проверки предметной области, код расширения и содержимое сайта остаются в проектах.

## Что уже реализовано

- `.open-project.json` со схемой: версии, примеры, npm, расширение, сайт, контейнер и направления публикации.
- `check`: состав репозитория, версии и lockfile, обязательные npm-скрипты, URL схемы с тегом, совпадение JSON/YAML, положительные и отрицательные примеры.
- `build`: проверки проекта, настоящий npm tarball и его установка в отдельный проект, VSIX и вызов host-тестов для минимального/stable VS Code, статический сайт и необязательный Docker-образ.
- `verify-artifacts`: полный состав файлов, размеры, SHA-256, commit, тег и репозиторий.
- Общие `verify.yml` и `release.yml`: Node 22/24, сохранение артефактов и публикация тех же файлов без пересборки.
- Публикация в GitHub Releases; по настройкам — npm, Marketplace, Open VSX и GHCR.

Из каталога проекта:

```sh
node ../open-tooling/bin/open-tooling.js check
node ../open-tooling/bin/open-tooling.js check --complete
node ../open-tooling/bin/open-tooling.js build
```

Результат находится в `dist/open-tooling/`: схема, текст спецификации, примеры, npm tarball, VSIX, архив сайта, Docker tar при включённой сборке, исходники, release notes, `release.json` и `SHA256SUMS`.

`--complete` требует все четыре продукта. Пока расширение или сайт не реализованы, это указывается явно с причиной; такой проект получает `complete: false`. В общем CI строгий режим включён по умолчанию.

Версии спецификации и npm совпадают. Расширение и сайт имеют свои версии и теги: `specification-vX.Y.Z`, `extension-vX.Y.Z`, `website-vX.Y.Z`. Каждый выпуск содержит весь настроенный комплект; тег определяет версию выпуска и публикацию соответствующего продукта в реестры.

Конфиги для `open-env` и `open-site` подготовлены. Существующие CI ещё не переключены: сначала нужен опубликованный commit этого репозитория. В [шаблонах workflow](templates/project/.github/workflows) один и тот же полный SHA нужно указать в `uses` и `tooling-ref`.

Публикация в реестры отключена в пилотах. Для включения нужны настройки доверенного издателя в npm/Marketplace/Open VSX либо доступ к GHCR. Сборка сама ничего не публикует. Подробности: [контракт](docs/project-contract.md), [выпуск](docs/releases.md), [миграция](docs/migration.md).
